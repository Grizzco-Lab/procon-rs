# CLAUDE.md

- Do not add any unused packages
- Add and remove dependencies with `cargo add` / `cargo rm` (-F for features; no unused features). Editing Cargo.toml by hand is fine for what cargo cannot do (feature groups, workspace settings, cleanup). Never edit Cargo.lock by hand.
- Call `cargo fmt` to format the code after finish editing. Use `prettier` for html.
- All the comments and docs must be in English. Chinese should never appear in the code. (The one exception is the page's Simplified Chinese dictionary, `web/i18n-zh.js`, which is data.)
- Keep it simple.
- rust has great inline doc feature (/// to struct, member, functions, and //! to the top of the file). You should leverage it as if you're really writing rust.
- follow what's there in the code; do not hallucinate.
- use core/alloc instead of std whenever possible. (I think this practice is good)

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Records Nintendo Switch gameplay for training datasets: Pro Controller input, timestamped, next to the console's video and sound. The README is the user guide; CONTRIBUTING.md has the same architecture in more words; `doc/index.html` is the illustrated write-up (screenshots in `doc/images/`, hero image `doc/demo.png`).

- `procon-proxy` (`src/bin/procon-proxy.rs`, config `proxy.toml`): USB proxy on a Raspberry Pi 4 between the Pro Controller and the Switch (USB gadget); streams timestamped frames over TCP (`[stream] port`, 7331) and takes replayed actions (`[replay] port`, 7332); resets the controller at start.
- `procon` (`src/bin/main.rs`, config `config.toml`): the studio on the Linux host with the capture card. Web dashboard with five apps: Studio (live preview, controller view incl. 3D, recording with sound and game settings, technique markers, replay, data, motion), Inkspector (recorded sessions frame by frame: labels, delays, sound, overlays, predictions, object labeling), Cuttlefish (a chat with the AI reviewer, saved in reviews; VOD reviews with comments and drawings; a Translate view for jargon over the glossary; a Knowledge view managing the `cuttlefish` store), Vision (detection and tracking with `gameplay-vision` through our classes, dataset overview, send to labels) and Predictor (AgentZero's IDM on any video, its predictions against the truth; AgentZero's policy online, on a video or on the live capture, where it can play the Switch). Every project is used from the page, not the CLI.
- `crates/gameplay-data`: recording format, per-frame alignment, labels, calibration; Python bindings (`python` feature, maturin) used by the AgentZero training project (`../AgentZero`).
- `crates/gameplay-vision`: object detection (YOLOv8 in candle, CPU; `cuda` feature) and SORT-like tracking on session video, the object label files shared with the labeling tool (`<annotations>/<session>/<segment>.objects.jsonl`, `classes.json`) and prelabeling; `hud`: the Salmon Run HUD (wave, timer, eggs) read from any video by blobs and template matching (`src/hud/templates.txt`, learned from our sessions' countdowns), and the timer's physics into a per-video `wave_starts.json` with `to_video_time(wave, timer_s)`; CLI `gameplay-vision` (`detect`, `track`, `prelabel`, `render`, `hud scan|read|time|learn`). Its README has the plan toward Salmon Run detection and 3D placement.
- `crates/cuttlefish`: the AI reviewer's backend and CLI: source importers (polite crawler; whole MediaWiki topics and sites in `wiki.rs` with dry runs and revision-based re-runs; yt-dlp, Discord export or bot), an inbox that sorts dropped material (prose, name tables, images, archives), chunks with multilingual-e5-small embeddings (candle), a flat vector index with a BM25 keyword index beside it (hybrid retrieval, `src/keyword.rs`), a glossary (seed `glossary.toml`: English, Japanese, Simplified Chinese where known, and the player's jargon; `# unsure:` marks names to check), and `Reviewer` (retrieval + Anthropic Messages API with frames: `review`, `ask`, `translate` and `explain` (a term or callout, glossary only), and `chat` with a conversation, `llm::Prompt::history`). Data folder outside the repo; keys only from `ANTHROPIC_API_KEY` / `DISCORD_BOT_TOKEN` / `DISCORD_USER_TOKEN` (the CLI loads the env file `scripts/run.sh` loads, `env_file`); `cuttlefish fetch discord` (`discord_fetch`) archives channels (given as links, `<guild>/<channel>` or ids; `--count` asks the server's search) with the user's own token and browser headers (`DISCORD_USER_AGENT`, `DISCORD_SUPER_PROPERTIES`, never made up), slowly and read-only, into `<knowledge>/inbox/discord/<guild>/<channel>/` (against Discord's terms; the inbox reads the raw JSONL; each document keeps `messages` rows: reply, thread, the video each is about (`video_local` when downloaded), and the times `moments` extracts); `--attachments list|videos|media` (`discord_media`) counts or downloads the uploaded VODs into `<knowledge>/media/discord/<guild>/<channel>/<message id>/` with a `media.jsonl` manifest, paced like the requests, resumable, re-reading a message's page when its signed link expired (the CDN serves an image in its file name's format, so a file is whole at the announced `Content-Length` and the manifest keeps the file's own size); `cuttlefish read-images` (`image_text`) sends each downloaded image once to the model backend with its message and the glossary's terms named there, for the text in it (its language, then English) and what it shows (tables, marks on maps, numbers), kept by SHA-256 in `<knowledge>/media/image-text.jsonl`, and the inbox puts each text under its image's link in the conversation's document (`discord::to_documents_with`), reading a channel again when texts of its images arrive (`Texts::digest`); `llm::Backend` picks the API or the Claude Code CLI (`claude_cli`: `claude -p` headless, no tools, on the user's subscription; `auto` = the API when the key is set, else the CLI). Every document, message row and index entry carries the game era (`game`: S2 before 2022-09-09, S3 after; a small ranking penalty for S2, `[Splatoon 2 era]` in the excerpt labels). `cuttlefish corpus` (`corpus`, `corpus_videos`, `corpus_reviews`): `build` writes `<knowledge>/corpus/vod-review.jsonl`, one reviewed VOD per line (video, poster, date, era, messages with their moments: `aligned` at `t_s`, or `needs_hud` for wave timers); `videos` downloads the YouTube VODs at 480p into `media/youtube/` (paced, resumable, unavailable ones remembered); `align` reads the HUD of the videos on disk with `gameplay-vision::hud` and writes `<stem>.wave_starts.json` beside each, which the build uses to place the timers; `reviews` creates or updates `<reviews>/discord-<id>/review.json` per VOD on disk (video by full path, comments at their moments with the reviewer as author and a Discord `source`, the rest as notes with `unplaced` moments; a special's hold its damage to Salmonids), hazard level, each keeping its data as `facts` (`stats::Facts`; `stats::summary` reads them in players' units for the Pedia and the card text: damage ÷10, ink in percent, frames at 60 per second, distances in game units, only conversions checked against Inkipedia pages in the store; hits to defeat each Salmonid from Inkipedia's HP, `stats::SALMONID_HP`; `CARD_FORMAT` in `raw/leanny/state.json` rebuilds older cards), one per Eggstra Work event and wave (spawn schedules per hazard level), a name table `leanny:names` for the glossary (keys as origins), and `corpus/eggstra_events.json` (dates from Inkipedia's list, one API request), which `corpus build` uses to tag VODs with `eggstra_event` (posted during the 48 h shift or the week after); `--dry-run` fetches nothing, re-runs fetch only changed files (304) and rebuild the cards only when something changed or with `--refresh`. Every card credits Lean; the persona quotes game-data numbers as exact for the version they name. See its README. `tools/capture/xcap.mjs` (Node, no packages; `lib/cdp.mjs` drives the user's own logged-in Chrome over DevTools on `~/.config/procon/browser-profile`, as `scripts/layout-check.mjs` does) captures the Salmon Run posts of the accounts the user follows on X with their replies, from the GraphQL JSON the page loads (DOM fallback), filtered by a three-language glossary (`lib/filter.mjs`), paced (4-10 s between page actions, pauses, per-run and per-day caps, a stop on 429/401/login) and resumable (`inbox/x/state.json`), into `<knowledge>/inbox/x/<handle>/posts.jsonl`; `x.rs` reads them in the inbox as one document per thread, source kind `x` (weight 1.0). ## Common Commands

```bash
cargo build --release                 # both binaries
cargo test --workspace                # procon and every crate's unit tests
cargo clippy --workspace --all-targets
cargo fmt                             # Rust; `prettier --write` for web/*.html and doc/index.html
./scripts/run.sh                      # studio with config.toml
./scripts/deploy.sh [ssh-host]        # cross-compile procon-proxy (aarch64-unknown-linux-musl, rust-lld), copy to the Pi, restart
./scripts/run-proxy.sh                # build and run procon-proxy on the Pi itself
cargo run --example fake_proxy 7397   # synthetic controller for a test studio
```

Both binaries take `--config <path>`; the studio saves dashboard settings to `<config>.state.json` next to it. Log level: `[logging] level` (error, warn, info, debug, trace).

Testing the studio: never touch a studio the user is running (port 8090 by default). Run a copy of the config with its own `[web] port`, `[proxy] address` pointing at `fake_proxy` (`replay_address` at the next port), and `[video] input = "screen"`, `""` or a recorded video file (looped as if live; never the capture card, which the user's studio holds). Send replayed actions only to `fake_proxy`.

## Architecture

**Proxy side**
- `src/device.rs`: the physical controller through hidapi; waits for it as long as it takes. `device::reset()` replugs it through sysfs (`authorized` 0/1) at proxy start: a controller the console knows over Bluetooth connects wirelessly when idle, which stalls the USB handshake (Switch stops after `subcommand 03`). Do not change its polling interval (`usbhid.jspoll`): on the Pi 4 it breaks the output endpoint and the Switch's handshake.
- `src/gadget.rs`: USB gadget (usb-gadget crate) with the Pro Controller's IDs; returns the `/dev/hidg*` path.
- `src/proxy.rs`: input (controller → Switch) and output (Switch → controller: rumble, LEDs, subcommands) on separate threads; a write to the controller blocks ~9 ms and the Switch sends rumble constantly. Each frame's `forward_us` is the time from reading the report to the Switch taking it (poll POLLOUT on the gadget); the dashboard shows it as the "Proxy +x ms" chip.
- `src/wake.rs`: while the Switch sleeps, Home restarts the DWC2 clock (`PCGCTL.StopPclk`, which also freezes `DSTS`) and sets `DCTL.RmtWkUpSig` through `/dev/mem`, as the driver's `dwc2_gadget_exit_clock_gating` does. The Switch 2 ignores it; the original Switch is untested.
- `src/priority.rs`: nice -10, `SCHED_FIFO` 50 as root, optional CPU affinity (`[performance]`).
- `src/dump.rs`: `Dumper` trait, `AsyncDumper` (own thread, drops on backpressure), `FileDumper`, `MultiDumper`; frames are `gameplay_data::frame::Frame`.
- `src/replay.rs`: JSON-line `Action`s, loaded from a session, `controller.bin` or `.jsonl`; the proxy's replay port applies the latest action to input reports (or, with `mix`, combines them: buttons OR-ed, each stick the controller's while pushed past `STICK_DEADZONE` (300 raw from 2048; the owner's sticks rest up to ~205 off it) and the gyro while turning faster than `GYRO_DEADZONE_DPS` (10 °/s), else the line's, so a person corrects it live; a line without sticks/gyro leaves them to the controller) before they are recorded and forwarded. A change here needs the proxy redeployed.

**Link**: `src/stream.rs`: proxy-side `FrameStreamer` (TCP, 8-byte header then 80-byte frames, heartbeats after 1 s without reports) and studio-side `receive_frames` (sequence gaps as dropped frames, clock offset as the minimum `host_now - proxy_ts` over 10 s).

**Studio side**
- `src/recorder.rs`: session folders `<prefix>YYYY-MM-DD_HH-MM-SS/` with `controller.bin`; start/pause/resume/stop.
- `src/video.rs`: ffmpeg grabber (owns the input, raw 1080p frames; restarted only by choosing another input), preview encoder (low-latency H.264 as fragmented MP4, one fragment per frame, played by a `<video>`), one recording encoder per file (constant rate, keyframe every second). The grabber logs each frame's kernel capture time (`-ts mono2abs -copyts` + `showinfo`); recordings start at the first frame's capture time; a queue of late frames (>120 ms for 3 s while idle) restarts the grabber. A `PolicyFeed` gets the same raw frames for the Predictor's live policy, thinned to its rate, each with its capture time (a full queue skips frames). The input may be a video file: `-re -stream_loop -1`, stamped with the wall clock by `setpts=RTCTIME`, for testing without a console.
- `src/audio.rs`: ffmpeg reads the `[video] audio_input` PulseAudio source continuously in 10 ms chunks (last 2 s kept); a recording's sound starts at the sample that arrived with its first frame and goes to the encoder on fd 3, as an Opus track in the same file.
- `src/studio.rs`: coordinator; `Command`s from the dashboard, starts/stops recorder and video together, writes `session.json` (with `GameSettings`: Splatoon 3 sensitivities, which scale gyro/stick into camera turns, and `markers`), saves settings to the state file. Technique markers: `MarkStart`/`MarkStop` (the open span lives in `Session`; Pause/Stop end it), `MarkLast`, `MarkUndo`, `SetTechniques` (added techniques in the state file); `session.json` holds the list and every change re-reads it first, since the Inkspector edits it too. `web/techniques.js`: the Techniques panel (default list with Pedia term ids, Chinese names as `tech.zh.<id>` in `i18n-zh.js`; keys 1–9, M span, B last N s, U undo; Checklist from `GET /api/inspect/markers`).
- `src/player.rs`: the Replay panel; sends loaded actions to the proxy's replay port at their `t_ms`.
- `src/motion.rs`: gyro + accelerometer orientation for Splatoon mode; Y recenters.
- `src/web.rs`: warp server with the page embedded from `web/` (also served at every app path), WebSocket `/ws` (`state` per input report, `status` twice a second, preview fMP4 as binary), `POST /api/command`, `/api/inspect/...`, `/api/cuttlefish/...`, `/api/vision/...`, `/api/predictor/...`. `src/bin/main.rs` logs warp's reports of clients that left mid-request (`IncompleteMessage`, connection reset, broken pipe: aborted video ranges when seeking, frames no longer wanted, a reload during a slow request) at debug, not error (`is_client_abort`). Nothing slow runs before the server listens: `Player::restore` (the last replay file; `path()` names it meanwhile) and `Cuttlefish::migrate` run on threads, since both may read a network mount; `scripts/run.sh` builds, then execs the binary.
- `web/player.js`: the video player every app shares (class `Player`, made from the Inkspector's): a source of exact frames (`{frames, fps, frame(n)}`, the Inkspector's endpoint, drawn on a canvas, played by a paced loop or the audio's clock) or a `<video>` (`{video, fps}`, frames followed with `requestVideoFrameCallback`, seeks land mid-frame), plus `thumb(n)`, `audio`, `sound`, `labels(n)` (a promise of `[truth, prediction]`) and `title`; transport in the app's `.controls` (play, ‹ ›, speed, Sound, Overlay: Full / Minimal / None, Go to…, position chip), keys on `document` while `enabled` (Space, arrows, Shift ×10, Home/End, G; never in inputs), scrubber with marks (`setMarks({ticks: [{n, kind, short?, id?, title?}], ranges: [{a, b, kind}]})`, colors from `--mark-<kind>`, click snaps to the nearest tick, `onMark`), neighbours strip (`neighbours: {radius, seconds}`: every frame, or on a time grid so nearby pauses reuse thumbnails), the full overlay (truth, and a prediction against it: key strips, stick rings, thin gyro bars, mismatched keys edged red; a video without a recording shows its prediction alone) and the Minimal one (`drawInputHud`), the labels table (`table`, truth over prediction, mismatches; `compact` drops the Valid column and the commas for a narrow column). Callbacks `onFrame(n)`, `onSeek(n)`, `onPlay(playing)`, `onMark(tick)`, `onError`. Apps add layers by appending to `screen` (Sketch, boxes, danmaku). Choices remembered under `procon-<remember>-*`.
- `src/inspect.rs` + `web/inspect.js`: Inkspector. Sessions under `[inspect] root`, frames decoded by ffmpeg in short cached windows at 360p, labels via `gameplay-data`, sound as WebM with ranges, delays from `[inspect] calibration` (AgentZero's `calibration.json`); `POST /api/inspect/delay` sets/removes a delay by hand; `GET/POST /api/inspect/markers` reads/replaces a session's technique markers (without `s`: every session's, with segment and frame, for the Studio's checklist and the Pedia's recorded examples); markers are drawn as scrubber bands, a lane of chips and an editable list, frame n at `start + n/fps - delay`. The page is the player (`framePlayer`) plus the session picker, tiles, delay and predictions inputs, R for a random frame; label.js reads `inspector.frame/info/marks` and hears `inspect-frame`. State in the URL (`/inspect/<session>?seg=&n=&delay=&pred=`, `&label=1` for the labeling mode).
- `src/objects.rs` + `web/label.js`: Inkspector labeling mode (Label toggle, L): object boxes per frame in `[inspect] annotations` (default `Annotations` next to the root): `classes.json` and `<session>/<segment stem>.objects.jsonl` (`{"frame", "boxes": [{"class", "x", "y", "w", "h", "id"?, "by": "user"|"model", "score"?}]}`, top-left and size as 0–1 fractions); `POST /api/inspect/objects` saves a frame atomically and keeps model boxes the page never loaded (with `frames: [{frame, boxes, base}]`, several in one write: `Annotations::save_frames`). Accept model (A) makes the selected model box, or all of the frame's, the user's (`by: user`, no score); Accept up to here (Shift+A) does so for every frame with model boxes after the last frame before this one a person fully reviewed (people's boxes only, since Follow adds model boxes to labeled frames), up to this one, in one save (count in the button's title, "Accepted N boxes on M frames" after). Labeled frames are marked on the scrubber (canvas, `drawMarks` in `inspect.js`, fainter with Label off; a click near a mark snaps to it); classes past Shift+0 have no key, `/` finds a class. STARTER_CLASSES (28: every named Salmonid of Lean's `CoopEnemyInfo` incl. the known-occurrence ones (goldie, griller, mudmouth, gold_mudmouth, chinook, mothership) and King Salmonids, plus golden_egg, player, dead_player, basket; append only, never rename) is the same list in `objects.rs` and `gameplay-vision` (a test checks).
- `src/follow.rs`: Follow (F) in the labeling mode: boxes of one frame tracked forward/backward by AgentZero's `agentzero-track-serve` (SAM 2.1 tiny, `src/agentzero/track/`, `[inspect] tracker`, default http://127.0.0.1:7340), proxied from a thread (`/api/inspect/follow/status|job|run|cancel|start`), written as model boxes with score and track id every 10 frames. Per object, not per frame (`apply_followed`): labeled frames do not stop it (`follow_span` is the count up to the segment's ends); on each frame the model boxes of the same ids give way and the followed box is added unless a person's box of the same class overlaps it (IoU > `COVERED_IOU` = 0.3), which stands for the object there (`covered` in the job); people's boxes and lines a person left empty are never changed; lost objects stop. `start` runs `tracker_command` in `tracker_dir` (default `uv run agentzero-track-serve --port <port>` in `../AgentZero`) in its own process group, killed with the studio. The tracker uses the GPU when it has ~1 GiB + 0.05 GiB/object free, else the CPU (~30x slower).
- `src/cuttlefish.rs` + `web/cuttlefish.js`: Cuttlefish, chat and VOD reviews. Four views switched by the tab strip `#cf-tabs` (marked in `cuttlefish.js`, hidden in the player): **Reviews** (`/cuttlefish`: the reviews, "Open a video", and the chat bar `p-cf-entry` kept at the bottom of the window like a chat app's input (the app fills the height below the top bar; its examples one sideways-scrolling row while the input is empty), whose message starts a review without a video and sends it), **Translate** (`/cuttlefish/translate`, `web/translate.js`, below), **Knowledge** (further below) and **Pedia** (`/cuttlefish/pedia[/<term id>]`, `web/pedia.js` + `src/pedia.rs` over `cuttlefish::pedia`: the glossary's Salmon Run terms in sections (every Salmonid, stage, weapon and special of Lean's name table among them), searchable in any language ignoring case, spaces, punctuation and full width (`glossary::loose`), with official names, the game-data fact cards first, slang, relations both ways, #vod-review quotes (mentions searched once and cached until the corpus or the names change; the reviews here listed once a minute), game-data fact cards (read on a thread when the store's index file changes, since a folder's mtime never changes on the rclone mount; `cards_pending` until then, and the page asks again), notes and deep questions, edited in place through the slang and `term-edit` endpoints). Cited sources and Pedia quotes open in the source popover (`web/source.js`, `GET source`: a #vod-review comment with its conversation and review moments, or the cited chunk). The mentor's avatar (`.cf-avatar`, `icons/app-cuttlefish.svg`) sits in every box where he can be asked: the bar, the chat in a review, the translator. A review is at `/cuttlefish/review/<id>?t=`, a video not reviewed yet at `/cuttlefish/video?kind=&ref=&start_s=&end_s=&t=`. Videos: a session segment, a local file or a YouTube range; comments at times/ranges with drawings. Each review is a folder `[cuttlefish] reviews/<id>/` with `review.json` and, when the video lives there, `video.<ext>` (`video.file`, a plain file name checked to stay in the folder): a YouTube range is downloaded by yt-dlp straight into a new review (title, channel, upload date saved in `video`) or, with `review`, into a chat's review without a video ("Attach a video", `p-cf-attach`; a session or file attaches by saving `video`), a local file can be copied in (`POST reviews/<id>/copy`), a session segment is never copied. `video` is optional (`Option<VideoRef>`, left out of the file when none); the library names such a review by its first message (`topic`). Deleting removes the folder. No download cache; `Cuttlefish::migrate` moves flat `<id>.json` reviews into folders at startup, with their videos from the old `~/.cache/procon-cuttlefish/yt-<hash>.mp4` (`cache_id`). The chat (`p-cf-chat`, beside the video or the main area without one): `POST /api/cuttlefish/chat` with `{message, history: [{role, text}], video?, t_s?, t_end_s?, review?}`; with a video and `t_s` the frames of the range or the moment around `t_s` (a sampling plan from `cuttlefish::sampling`: a moment is 5 fps within ±1 s and 1 fps from t−4 to t+2 s; a range (at most 100 s) is placed by frame difference and wave events, two passes over 20 s; never upscaled; JPEGs cached on disk by `src/cuttlefish/frames.rs`) and the review's comments near it go along (`video_context`), to `cuttlefish::review::chat` over the shared store of `src/knowledge.rs`; answers `{text, sources, comments}`; 501 while it cannot start (no backend: key from `ANTHROPIC_API_KEY` only, or the Claude CLI; `GET knowledge/model` tells the page). The page owns the review: it appends the user turn (with the moment/range it was asked with, from the "With the video" choice: moment, range, none) and Cuttlefish's turn (`sources`, the ids of the `comments` it added, which join the review as his) to `messages` and saves; the reply is saved even after the review was left (`putReview`). Times in answers (`1:23`, `83.5 s`) seek the video, `[S1]` links its source; the examples (`cf.chat.examples` in the i18n tables: questions about one's play, in the page's language) rotate as placeholders and are chips in an empty chat, followed by three demo questions drawn at random from `web/demo-questions.js` (`DEMO_QUESTIONS.en/zh`: questions the game-data fact cards answer with exact numbers, some needing #vod-review too; served as `/demo-questions.js`), with a video after two chips tied to the moment (`cf.ask.moment`, `cf.chat.rangeExample`, which also pick the "With the video" choice). `web/sketch.js` is the drawing layer both use (shapes in 0–1 coordinates). `review.json` may hold `notes` (whole-video comments, `{id, author, text, created_ms, edited_ms?}`) and `messages` (`{id, role, text, t_s?, t_end_s?, sources?, comments?, created_ms}`); both absent in older files, not written when empty. YouTube reviews lacking a title get title/channel/upload date from `yt-dlp --skip-download --print` on a thread, once per run, when listed or opened (`look_up_meta`; `GET reviews` lists the ones under way in `fetching`). `GET reviews` answers from memory (`ReviewList`: read at startup on a thread after `migrate`, 16 files at once, since every review folder on the rclone mount is a round trip once its directory cache expires; the studio's own writes update it; older than 30 s it is served while read again in the background, `refreshing`, which the page polls, for reviews written by `cuttlefish corpus reviews`); `save_review` keeps them when the page's copy lacks them, and `PUT` answers with the video. `GET thumb?<video>&t_ms=` is one small JPEG (ffmpeg, 144 lines, in-memory cache of 600, browser-cacheable) for the shared player's neighbours strip (every 0.5 s by default, `cf-spacing`). - `src/predictor.rs` + `web/predictor.js`: Predictor (`/predictor/<video key>/<checkpoint>?t=`). The online mode (`src/predictor/online.rs`, the Predict panel's model switch "AgentZero online", `po.*` keys, `/predictor/online`, `/api/predictor/online/status|checkpoints|labels|start|stop|play|release|limits|measure`): AgentZero's policy (`runs/policy/*/best.pt`) via `uv run agentzero-play --dry-run --json` (needs AgentZero's `--json`, read from `--help`), one at a time in its own process group (Stop and the studio's exit/Ctrl-C: SIGTERM, SIGKILL after `KILL_AFTER`). ## Target Platform
