# CLAUDE.md

- Do not add any unused packages
- Add and remove dependencies with `cargo add` / `cargo rm` (-F for features; no unused features). Editing Cargo.toml by hand is fine for what cargo cannot do (feature groups, workspace settings, cleanup). Never edit Cargo.lock by hand.
- Call `cargo fmt` to format the code after finish editing. Use `prettier` for html.
- All the comments and docs must be in English. Chinese should never appear in the code. (The one exception is the page's Simplified Chinese dictionary, `web/i18n-zh.js`, which is data.)
- Keep it simple.
- rust has great inline doc feature (/// to struct, member, functions, and //! to the top of the file). You should leverage it as if you're really writing rust.
- follow what's there in the code; do not hallucinate.
- use core/alloc instead of std whenever possible. (I think this practice is good)

## Project Overview

Records Nintendo Switch gameplay for training datasets: Pro Controller input, timestamped, next to the console's video and sound. The README is the user guide; CONTRIBUTING.md has the same architecture in more words; `doc/index.html` is the illustrated write-up (screenshots in `doc/images/`, hero image `doc/demo.png`).

- `procon-proxy` (`src/bin/procon-proxy.rs`, config `proxy.toml`): USB proxy on a Raspberry Pi 4 between the Pro Controller and the Switch (USB gadget); streams timestamped frames over TCP (`[stream] port`, 7331) and takes replayed actions (`[replay] port`, 7332); resets the controller at start.
- `procon` (`src/bin/main.rs`, config `config.toml`): the studio on the Linux host with the capture card. Web dashboard with five apps: Studio (live preview, controller view incl. 3D, recording with sound and game settings, replay, data, motion), Inkspector (recorded sessions frame by frame: labels, delays, sound, overlays, predictions, object labeling), Cuttlefish (a chat with the AI reviewer, saved in reviews; VOD reviews with comments and drawings; a Translate view for jargon over the glossary; a Knowledge view managing the `cuttlefish` store), Vision (detection and tracking with `gameplay-vision` through our classes, dataset overview, send to labels) and Predictor (AgentZero's IDM on any video, its predictions against the truth). Every project is used from the page, not the CLI.
- `crates/gameplay-data`: recording format, per-frame alignment, labels, calibration; Python bindings (`python` feature, maturin) used by the AgentZero training project (`../AgentZero`).
- `crates/gameplay-vision`: object detection (YOLOv8 in candle, CPU; `cuda` feature) and SORT-like tracking on session video, the object label files shared with the labeling tool (`<annotations>/<session>/<segment>.objects.jsonl`, `classes.json`) and prelabeling; CLI `gameplay-vision` (`detect`, `track`, `prelabel`, `render`). Its README has the plan toward Salmon Run detection and 3D placement.
- `crates/cuttlefish`: the AI reviewer's backend and CLI: source importers (polite crawler, MediaWiki, yt-dlp, Discord export or bot), an inbox that sorts dropped material (prose, name tables, images, archives), chunks with multilingual-e5-small embeddings (candle), a flat vector index, a glossary (seed `glossary.toml`: English, Japanese, Simplified Chinese where known, and the player's jargon; `# unsure:` marks names to check), and `Reviewer` (retrieval + Anthropic Messages API with frames: `review`, `ask`, `translate` and `explain` (a term or callout, glossary only), and `chat` with a conversation, `llm::Prompt::history`). Data folder outside the repo; keys only from `ANTHROPIC_API_KEY` / `DISCORD_BOT_TOKEN`. See its README.
- `cargo run --example fake_proxy [port]` stands in for the proxy.

## Common Commands

```bash
cargo build --release                 # both binaries
cargo test --workspace                # procon and every crate's unit tests
cargo clippy --workspace --all-targets
cargo fmt                             # Rust; `prettier --write` for web/*.html and doc/index.html
./scripts/run.sh                      # studio with config.toml
./scripts/deploy.sh [ssh-host]        # cross-compile procon-proxy (aarch64-unknown-linux-musl, rust-lld), copy to the Pi, restart
./scripts/run-proxy.sh                # build and run procon-proxy on the Pi itself
cargo run --example fake_proxy 7397   # synthetic controller for a test studio
```

Both binaries take `--config <path>`; the studio saves dashboard settings to `<config>.state.json` next to it. Log level: `[logging] level` (error, warn, info, debug, trace).

Testing the studio: never touch a studio the user is running (port 8090 by default). Run a copy of the config with its own `[web] port`, `[proxy] address` pointing at `fake_proxy`, and `[video] input = "screen"` or `""`.

## Architecture

**Proxy side**
- `src/device.rs`: the physical controller through hidapi; waits for it as long as it takes. `device::reset()` replugs it through sysfs (`authorized` 0/1) at proxy start: a controller the console knows over Bluetooth connects wirelessly when idle, which stalls the USB handshake (Switch stops after `subcommand 03`). Do not change its polling interval (`usbhid.jspoll`): on the Pi 4 it breaks the output endpoint and the Switch's handshake.
- `src/gadget.rs`: USB gadget (usb-gadget crate) with the Pro Controller's IDs; returns the `/dev/hidg*` path.
- `src/proxy.rs`: input (controller → Switch) and output (Switch → controller: rumble, LEDs, subcommands) on separate threads; a write to the controller blocks ~9 ms and the Switch sends rumble constantly. Each frame's `forward_us` is the time from reading the report to the Switch taking it (poll POLLOUT on the gadget); the dashboard shows it as the "Proxy +x ms" chip.
- `src/wake.rs`: while the Switch sleeps, Home restarts the DWC2 clock (`PCGCTL.StopPclk`, which also freezes `DSTS`) and sets `DCTL.RmtWkUpSig` through `/dev/mem`, as the driver's `dwc2_gadget_exit_clock_gating` does. The Switch 2 ignores it; the original Switch is untested.
- `src/priority.rs`: nice -10, `SCHED_FIFO` 50 as root, optional CPU affinity (`[performance]`).
- `src/dump.rs`: `Dumper` trait, `AsyncDumper` (own thread, drops on backpressure), `FileDumper`, `MultiDumper`; frames are `gameplay_data::frame::Frame`.
- `src/replay.rs`: JSON-line `Action`s, loaded from a session, `controller.bin` or `.jsonl`; the proxy's replay port applies the latest action to input reports (or, with `mix`, combines them) before they are recorded and forwarded.

**Link**: `src/stream.rs`: proxy-side `FrameStreamer` (TCP, 8-byte header then 80-byte frames, heartbeats after 1 s without reports) and studio-side `receive_frames` (sequence gaps as dropped frames, clock offset as the minimum `host_now - proxy_ts` over 10 s).

**Studio side**
- `src/recorder.rs`: session folders `<prefix>YYYY-MM-DD_HH-MM-SS/` with `controller.bin`; start/pause/resume/stop.
- `src/video.rs`: ffmpeg grabber (owns the input, raw 1080p frames; restarted only by choosing another input), preview encoder (low-latency H.264 as fragmented MP4, one fragment per frame, played by a `<video>`), one recording encoder per file (constant rate, keyframe every second). The grabber logs each frame's kernel capture time (`-ts mono2abs -copyts` + `showinfo`); recordings start at the first frame's capture time; a queue of late frames (>120 ms for 3 s while idle) restarts the grabber.
- `src/audio.rs`: ffmpeg reads the `[video] audio_input` PulseAudio source continuously in 10 ms chunks (last 2 s kept); a recording's sound starts at the sample that arrived with its first frame and goes to the encoder on fd 3, as an Opus track in the same file.
- `src/studio.rs`: coordinator; `Command`s from the dashboard, starts/stops recorder and video together, writes `session.json` (with `GameSettings`: Splatoon 3 sensitivities, which scale gyro/stick into camera turns), saves settings to the state file.
- `src/player.rs`: the Replay panel; sends loaded actions to the proxy's replay port at their `t_ms`.
- `src/motion.rs`: gyro + accelerometer orientation for Splatoon mode; Y recenters.
- `src/web.rs`: warp server with the page embedded from `web/`, WebSocket `/ws` (`state` per input report, `status` twice a second, preview fMP4 as binary), `POST /api/command`, `/api/inspect/...`, `/api/cuttlefish/...`, `/api/vision/...`, `/api/predictor/...`. `src/bin/main.rs` logs warp's reports of clients that left mid-request (`IncompleteMessage`, connection reset, broken pipe: aborted video ranges when seeking, frames no longer wanted, a reload during a slow request) at debug, not error (`is_client_abort`). Nothing slow runs before the server listens: `Player::restore` (the last replay file; `path()` names it meanwhile) and `Cuttlefish::migrate` run on threads, since both may read a network mount; `scripts/run.sh` builds, then execs the binary.
- `web/player.js`: the video player every app shares (class `Player`, made from the Inkspector's): a source of exact frames (`{frames, fps, frame(n)}`, the Inkspector's endpoint, drawn on a canvas, played by a paced loop or the audio's clock) or a `<video>` (`{video, fps}`, frames followed with `requestVideoFrameCallback`, seeks land mid-frame), plus `thumb(n)`, `audio`, `sound`, `labels(n)` (a promise of `[truth, prediction]`) and `title`; transport in the app's `.controls` (play, ‹ ›, speed, Sound, Overlay: Full / Minimal / None, Go to…, position chip), keys on `document` while `enabled` (Space, arrows, Shift ×10, Home/End, G; never in inputs), scrubber with marks (`setMarks({ticks: [{n, kind, short?, id?, title?}], ranges: [{a, b, kind}]})`, colors from `--mark-<kind>`, click snaps to the nearest tick, `onMark`), neighbours strip (`neighbours: {radius, seconds}`: every frame, or on a time grid so nearby pauses reuse thumbnails), the full overlay (truth, and a prediction against it: key strips, stick rings, thin gyro bars, mismatched keys edged red; a video without a recording shows its prediction alone) and the Minimal one (`drawInputHud`), the labels table (`table`, truth over prediction, mismatches; `compact` drops the Valid column and the commas for a narrow column). Callbacks `onFrame(n)`, `onSeek(n)`, `onPlay(playing)`, `onMark(tick)`, `onError`. Apps add layers by appending to `screen` (Sketch, boxes, danmaku). Choices remembered under `procon-<remember>-*`.
- `src/inspect.rs` + `web/inspect.js`: Inkspector. Sessions under `[inspect] root`, frames decoded by ffmpeg in short cached windows at 360p, labels via `gameplay-data`, sound as WebM with ranges, delays from `[inspect] calibration` (AgentZero's `calibration.json`); `POST /api/inspect/delay` sets/removes a delay by hand. The page is the player (`framePlayer`) plus the session picker, tiles, delay and predictions inputs, R for a random frame; label.js reads `inspector.frame/info/marks` and hears `inspect-frame`. State in the hash (`#inspect/s=&seg=&n=&delay=&pred=`).
- `src/objects.rs` + `web/label.js`: Inkspector labeling mode (Label toggle, L): object boxes per frame in `[inspect] annotations` (default `Annotations` next to the root): `classes.json` and `<session>/<segment stem>.objects.jsonl` (`{"frame", "boxes": [{"class", "x", "y", "w", "h", "id"?, "by": "user"|"model", "score"?}]}`, top-left and size as 0–1 fractions); `POST /api/inspect/objects` saves a frame atomically and keeps model boxes the page never loaded. Labeled frames are marked on the scrubber (canvas, `drawMarks` in `inspect.js`, fainter with Label off; a click near a mark snaps to it); classes past Shift+0 have no key, `/` finds a class. STARTER_CLASSES (21, incl. dead_player, basket, King Salmonids) is the same list in `objects.rs` and `gameplay-vision` (a test checks).
- `src/follow.rs`: Follow (F) in the labeling mode: boxes of one frame tracked forward/backward by AgentZero's `agentzero-track-serve` (SAM 2.1 tiny, `src/agentzero/track/`, `[inspect] tracker`, default http://127.0.0.1:7340), proxied from a thread (`/api/inspect/follow/status|job|run|cancel|start`), written as model boxes with score and track id every 10 frames. Never writes a frame a person labeled (`follow_span` stops before it, `apply_followed` skips it); replaces model boxes of the same ids; lost objects stop. `start` runs `tracker_command` in `tracker_dir` (default `uv run agentzero-track-serve --port <port>` in `../AgentZero`) in its own process group, killed with the studio. The tracker uses the GPU when it has ~1 GiB + 0.05 GiB/object free, else the CPU (~30x slower).
- `src/cuttlefish.rs` + `web/cuttlefish.js`: Cuttlefish, chat and VOD reviews. Three views switched by the tab strip `#cf-tabs` (marked in `cuttlefish.js`, hidden in the player): **Reviews** (`#cuttlefish`: the reviews, "Open a video", and the chat bar `p-cf-entry` kept at the bottom of the window like a chat app's input (the app fills the height below the top bar; its examples one sideways-scrolling row while the input is empty), whose message starts a review without a video and sends it), **Translate** (`#cuttlefish/view=translate`, `web/translate.js`, below) and **Knowledge** (further below). The mentor's avatar (`.cf-avatar`, `icons/app-cuttlefish.svg`) sits in every box where he can be asked: the bar, the chat in a review, the translator. Videos: a session segment, a local file or a YouTube range; comments at times/ranges with drawings. Each review is a folder `[cuttlefish] reviews/<id>/` with `review.json` and, when the video lives there, `video.<ext>` (`video.file`, a plain file name checked to stay in the folder): a YouTube range is downloaded by yt-dlp straight into a new review (title, channel, upload date saved in `video`) or, with `review`, into a chat's review without a video ("Attach a video", `p-cf-attach`; a session or file attaches by saving `video`), a local file can be copied in (`POST reviews/<id>/copy`), a session segment is never copied. `video` is optional (`Option<VideoRef>`, left out of the file when none); the library names such a review by its first message (`topic`). Deleting removes the folder. No download cache; `Cuttlefish::migrate` moves flat `<id>.json` reviews into folders at startup, with their videos from the old `~/.cache/procon-cuttlefish/yt-<hash>.mp4` (`cache_id`). The chat (`p-cf-chat`, beside the video or the main area without one): `POST /api/cuttlefish/chat` with `{message, history: [{role, text}], video?, t_s?, t_end_s?, review?}`; with a video and `t_s` the frames of the range or the moment around `t_s` (ffmpeg, 2 fps, 720p, `jpeg_frames`) and the review's comments near it go along (`video_context`), to `cuttlefish::review::chat` over the shared store of `src/knowledge.rs`; answers `{text, sources, comments}`; 501 while it cannot start (key from `ANTHROPIC_API_KEY` only, `GET knowledge/model` tells the page). The page owns the review: it appends the user turn (with the moment/range it was asked with, from the "With the video" choice: moment, range, none) and Cuttlefish's turn (`sources`, the ids of the `comments` it added, which join the review as his) to `messages` and saves; the reply is saved even after the review was left (`putReview`). Times in answers (`1:23`, `83.5 s`) seek the video, `[S1]` links its source; the examples (`cf.chat.examples` in the i18n tables: questions about one's play, in the page's language) rotate as placeholders and are chips in an empty chat, with a video after two chips tied to the moment (`cf.ask.moment`, `cf.chat.rangeExample`, which also pick the "With the video" choice). `web/sketch.js` is the drawing layer both use (shapes in 0–1 coordinates). `review.json` may hold `notes` (whole-video comments, `{id, author, text, created_ms, edited_ms?}`) and `messages` (`{id, role, text, t_s?, t_end_s?, sources?, comments?, created_ms}`); both absent in older files, not written when empty. YouTube reviews lacking a title get title/channel/upload date from `yt-dlp --skip-download --print` on a thread, once per run, when listed or opened (`look_up_meta`; `GET reviews` lists the ones under way in `fetching`); `save_review` keeps them when the page's copy lacks them, and `PUT` answers with the video. `GET thumb?<video>&t_ms=` is one small JPEG (ffmpeg, 144 lines, in-memory cache of 600, browser-cacheable) for the shared player's neighbours strip (every 0.5 s by default, `cf-spacing`). The video plays in the shared player; the comments are its marks (ticks and range bands, the AI's in `--mark-ai`), the drawings (Sketch) and the danmaku (comments over the video as playback crosses their `t_s`, float or slide, their drawings held as long) are layers over it, and the links to the original YouTube video follow `start_s + player.time()`.
- `web/translate.js` (+ `Knowledge::translate` in `src/knowledge.rs`, the history in `src/cuttlefish.rs`): the Translate view, a chat-like translator: the history panel, then a bar like the library's (`p-cf-entry`: chips with the player's sentences (data in the script, like the glossary), the avatar, the input, a target-language picker remembered as `procon-cuttlefish-target`, Send). `POST /api/cuttlefish/translate` `{text, target}`: the glossary (no store, no model) gives the terms the text mentions, or a bare term's entry (`term: true`) with its name in the target as the translation; with `ANTHROPIC_API_KEY` the crate's `review::translate` translates a sentence and `review::explain` explains a term, else `needs_key`. The page shows a bare term's entry at once from `GET knowledge/glossary` while the model answers. Each answer (`id`, `created_ms`, text, target, terms as `Term`s, translation, explanation) is appended to `<reviews>/translations.jsonl` (`TRANSLATIONS_KEPT` = 500, rewritten whole through `write_atomic`); `GET translations` lists it newest first, `DELETE translations` clears it. Entries show the translation with Copy, the explanation, and each term as "form in the text → name in the target" with its definition and every name.
- `src/knowledge.rs` + `web/knowledge.js`: Cuttlefish's Knowledge view (`#cuttlefish/view=knowledge`; the tab strip `#cf-tabs`, a segmented switch like the top bar's with what each view holds as its tooltip, starts the content column above the library and is hidden in the player), managing the store only (asking is the chat's, translating and glossary lookups the Translate view's): two `.k-col` columns, Import / Search on the left, What the store holds (stats tiles, keys, overview, reports) / Documents / Assets on the right. The store and E5 embedder load once (`Knowledge::loaded`) and serve search, imports and the chat (`cuttlefish::review::chat` over borrowed parts, `Knowledge::chat`); the model client is made per request from `ANTHROPIC_API_KEY` (501 without; the page only learns set/not set, `GET model`). Imports (`cuttlefish::ingest`, a `Sink` that logs into the job) run one at a time on a thread, with cancel. The **inbox** (`<knowledge>/inbox/`, `cuttlefish::inbox`): files dropped there or uploaded (`POST knowledge/upload?path=`, streamed; `knowledge::routes` also serves `GET thumb`) are classified and routed: prose → documents, multilingual name tables (JSON/YAML/TOML/CSV/PO, locale families like `locales/*/x.json`, `USen.json`) → `terms/<id>.json` merged into the glossary (`cuttlefish::tables`), images → `assets.json` with thumbnails from ffmpeg in the local cache and links to glossary terms (`cuttlefish::assets`), archives unpacked by `bsdtar`, code/binaries skipped; `inbox.json` dedups by size/time/hash, `reports/` keeps a report per import. `GET overview` (no model needed), `assets`, `report(s)`, `POST delete`. The knowledge folder (default `Knowledge` next to the Inkspector root, may be Dropbox) is written only through `store::write_atomic`, never locked; small data tables without languages become text documents (under 1 MB); the model and other caches are in `store::cache_dir()` (`~/.cache/procon-cuttlefish`). `~/.local/share/cuttlefish` and `~/.cache/cuttlefish` belong to another program: `store::migrate` copies only our entries from the former, verifies, and moves them into `procon-migrated-<date>.safe-to-delete/` there, never touching foreign files; `Store::open` refuses it. The CLI finds the knowledge folder through the studio config (`--config`, default `./config.toml`), else `$CUTTLEFISH_DATA`, else fails.
- `src/vision.rs` + `web/vision.js`: Vision (`#vision/s=&seg=&n=`). One run at a time on a thread (`POST /api/vision/run`, poll `GET job`, `POST cancel`): `gameplay_vision` frames → `Detector` (loaded once per model/device and reused) → `Tracker` (ids copied onto detections by IoU), per-frame decode/network/total ms; results in `[vision] results` as `<session>/<stem>.objects.jsonl` (label format + `"ms"`) and `.run.json`. `POST send` maps classes (`labels::map_classes`) and merges into the annotations by the prelabel rule under the labeling mode's lock (`Annotations::merge_model_boxes`); the link opens `#inspect/...&label=1`. `GET results` shows only our classes (`classes.json` after the page's `map`, others counted in `hidden`; `all=1` for raw COCO, the page's "experimental" toggle); `GET overview` counts user/model boxes per class and labeled frames (`is_reviewed`) per segment against `TARGET_FRAMES` (200; detector training waits for it). The segment plays in the shared player (the Inkspector's frames), the boxes an SVG layer over it, the processed frames as marks on the scrubber; N/P and ‹ Boxes › jump between them. `cuda` feature forwards to `gameplay-vision/cuda`.
- `src/predictor.rs` + `web/predictor.js`: Predictor (`#predictor/key=&ckpt=&t=`). Runs `uv run agentzero-predict` in `[predictor] agentzero` (default `../AgentZero`) as a child process, one at a time: sessions as `<session dir> --segment <file>`, other videos (Cuttlefish reviews, files) as `--video <file>`, `--start-s/--end-s`, `--cpu`, each only if the command's `--help` lists it (read once, `info?refresh=1`); parses `progress d/t` on stderr, keeps the output's last lines, detects CUDA out-of-memory. Output `<results>/<video key>/<checkpoint>/pred.jsonl` (written as `.part`, renamed on success) and `run.json` (the `Job`: source, range, fps, `frame_offset`, play query, session). Checkpoints: `runs/*/best.pt`, newest first. `GET labels` gives a window of predictions (+ truth via `Inspector::labels` for sessions); `GET agreement` F1 per button and Pearson r per stick axis, gyro pitch/yaw and `camera_turn` (the IDM's extra key; truth has none). The page opens the video in the shared player (`/api/cuttlefish/video`, thumbnails from `thumb`), whose Full overlay and labels table compare truth and prediction per frame; a clone of the SVG controller, the button probabilities, a canvas timeline around the playhead and the agreement panel follow `onFrame`. Layout: the video panel (screen sized by `--p-video` from the window height, scrubber, strip) and a sticky `.p-p-side` column (run, Predicted, Frames with the player's `compact` table, Agreement), `display: contents` on narrow windows and phones; the Inkspector likewise has its strip in the Frame panel, labels and session beside it.

**Dashboard (`web/`)**: one page, five apps switched by hash (`#studio`, `#inspect/...`, `#cuttlefish/...`, `#vision/...`, `#predictor/...`) without reloading; app links as a dock-like left rail (apps at the top; `.bar-tools`, the language switch, View and the `.rail-toggle` chevron, fixed at its foot; `data-rail` compact (50 px tiles, names as delayed tooltips beside the icons, the open app on a tinted tile with a mark on the rail's edge, icons lifting on hover; no filters over the live video) or expanded (icons with names, `procon-rail`, the View menu's Rail row or the chevron); each theme's `--rail-*` tokens set its surface, tiles and mark) or a segmented switch in the top bar (`data-nav`; other apps' names become tooltips below 1440 px, 1720 px for the Inkspector and Joy), reordered by drag or Alt+arrows (`procon-app-order` in `localStorage`, apps it does not name go last). Top bar: navigation, passive status (`.status-strip .chip`: dot and word, no border or hover, details in `title`; the open app's `data-app-only` group first, then the studio's; healthy link indicators keep only their dot when an app adds status and the bar is short) and actions (`.tool-button`) look different; one row down to ~1060 px of page (`container: page`), then the status takes the second row. The Inkspector's session picker is in its Session card. The View popover (a two-column grid) sets `data-theme` (studio, joy, telemetry, salmon; the Salmon Run theme is `web/art/salmon.css`), `data-layout` (auto, phone), `data-nav` and `data-rail`, stored in `localStorage` (`procon-*`), and the language. `web/i18n.js` (loaded first) holds the English table, `t(key, values)` (`{name}` placeholders, functions for plurals, English fallback), `applyI18n` for `data-i18n`, `data-i18n-html`, `data-i18n-placeholder`, `data-i18n-title` and `data-i18n-aria-label`, and the language buttons (`data-pick-lang`, `procon-lang`, default from the browser); `web/i18n-zh.js` adds `I18N.zh`. A change fires `lang-change` so scripts redraw their own text. Cuttlefish with its Translate and Knowledge views is translated; other apps can adopt keys as they go. Chinese game terms follow the official Simplified Chinese Splatoon 3 names; fonts have CJK fallbacks (`--font-cjk`). The Studio's preview pauses and its views stop drawing while another app is shown or the tab is hidden; the other apps stop polling and playback likewise (background jobs keep running on the server). `web/controller3d.js`: three.js from jsdelivr, extrudes the SVG view's outline and reuses its theme colors; the SVG is the fallback without WebGL or the CDN. The input overlay (`drawInputHud` in `app.js`) draws sticks, buttons and turn rates over the Studio preview (held back by the preview delay) and is the shared player's Minimal overlay.

**gameplay-data (`crates/gameplay-data`)**: `frame` (80-byte record), `controller` (`controller.bin` as columns), `session` (`session.json` model; old sessions lack fields), `align` (frame `n` at `start_unix_ms + n * 1000 / fps - video_delay_ms`; actions per frame), `labels` (JSON lines for truth and predictions), `calibration` (delay applied: manual > session with high/medium confidence > setup era), `python` (bindings).

## Target Platform
- Proxy: `aarch64-unknown-linux-musl` (static ARM64 binary, linked by rust-lld; see `.cargo/config.toml`, `scripts/deploy.sh`), built with `--no-default-features` (the `studio` feature holds the studio-only crates), run as root on the Pi.
- Studio: a Linux host with ffmpeg (NVENC by default), PulseAudio and a V4L2 capture card.
